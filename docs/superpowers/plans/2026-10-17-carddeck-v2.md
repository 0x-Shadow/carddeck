# Carddeck v2 (Images, Animations, MCP Agent, Self-Hosting) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Carddeck real images (upload + URL, embedded in PPTX), AI-directed animations in the .pptx and web present mode, an MCP server so agents like OpenCode can build decks end-to-end, and one-container self-hosting.

**Architecture:** Extend the existing Turborepo in place: a motion model in `packages/core` (pure, deterministic plan expansion), an `asset` table + filesystem store under `DATA_DIR/assets`, OOXML animation injection via the existing JSZip post-processing step in `packages/pptx`, a worker post-generation step that derives/fills motion plans, and a new `apps/mcp` stdio workspace that operates on the same `DATA_DIR` (like the worker) and returns structured tool results.

**Tech Stack:** Next.js 15 / React 19, better-sqlite3 + Drizzle (lazy migrations), pptxgenjs + html2pptx + JSZip, Playwright (PDF), `@modelcontextprotocol/sdk` + zod, Vitest + Playwright tests, Turbo.

**Spec:** `docs/superpowers/specs/2026-10-17-carddeck-v2-design.md`

## Global Constraints

- Asset upload cap: **10 MB** (`MAX_ASSET_BYTES = 10 * 1024 * 1024`); accepted mimes: `image/png`, `image/jpeg`, `image/webp`, `image/gif` (no SVG).
- Remote image fetch (export + MCP): **http/https only** (block `file:` and every other scheme), **5 s timeout**, **10 MB cap**, `image/*` content-type only; failure → `null` → existing placeholder fallback.
- Motion delays clamped to **0–5000 ms**; builds per slide capped at **12**; slides capped at deck card count.
- Deck PATCH motion contract: `{ motionPreset: MotionPreset }` (server derives) **or** `{ motion: MotionPlan }` (validated). Worker fills `deck.motion.slides` after cards settle when preset ≠ `none`.
- Export kill switch: env `CARDDECK_MOTION=off` disables PPTX animation injection entirely.
- Route modules export only HTTP verb names (Next 15 build rule). Worker/MCP reach web code via relative-path imports (established convention). `DATA_DIR` always via `resolveDataDir`.
- Every task: TDD (failing test → implement → pass → commit). `npm test` green at each commit.

## Review Focus (spec-implied failure modes; each has a test in its owning task)

1. **Shared-deck images:** deck shared *after* upload → signed-out reader/PDF must show images (public gating on asset GET). → T3 test "serves assets for public decks without a session".
2. **Path traversal:** hostile `assetId`/`deckId` (`../..`, URL-encoded) must 404, never read outside `DATA_DIR/assets`. → T3 test "rejects traversal-shaped ids".
3. **SSRF/protocol in remote images:** `file://`, `ftp://`, `data:` URLs must resolve to `null` (no fetch attempt). → T5 test "refuses non-http(s) schemes".
4. **Motion XML corruption:** plan with more builds than shapes, zero-shape slides, or missing slide files must leave the zip valid and other slides untouched. → T7 tests "clamps builds to shape count" + "leaves unplanned slides byte-identical".
5. **MCP wait timeout:** a generation that never finishes must return `{ ok: true, status, note }` at the deadline — the tool call must not hang the client. → T9 test "returns partial state at timeout".
6. **Abort swallow is surgical:** only `AbortError` is swallowed; a real network failure still surfaces. → T1 test "non-abort rejections still reject".
